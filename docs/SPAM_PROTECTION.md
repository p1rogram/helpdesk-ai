# Защита модели от спама и перегрузки гостями

Статус: **реализовано** (кроме 3.5 и 3.6 — по мере появления реального трафика). Документ
сохранён как обоснование: кто и как может перегрузить модель, что защищает и почему выбраны именно
эти меры.

## 0. Что сделано

| Мера | Где | Конфиг |

| Гость = устройство: подписанная cookie `hd_device` на год, имя не хранится | `routes/auth.ts` | — |

## 1. Модель угроз

Что именно дорого: каждое сообщение пользователя — это до двух вызовов модели (анализ + ответ)
и, при включённом RAG, локальная векторизация. Бюджет тратится в токенах и во времени ответа для
остальных. Помимо денег есть второй ресурс — очередь операторов: поток фальшивых заявок хуже
потока запросов к модели.

| Источник | Что может сделать | Почему это возможно |
|---|---|---|
| Гость сайта (без учётной записи) | войти под любым именем, слать сообщения в цикле, открывать много «гостей» с разных вкладок/IP | `WEB_GUEST_LOGIN=true`: вход анонимный, личность не проверяется |
| Демо-студент (`WEB_DEMO_LOGIN=true`) | то же плюс заявки специалисту | на проде выключен (`server-setup.sh` ставит `false`) |
| Настоящий студент через Telegram / SSO | автоматизировать себя: скрипт с валидным токеном | учётная запись настоящая, но токен JWT живёт долго и не привязан к устройству |
| Бот-сеть | распределённый перебор IP, обход IP-лимитов | у гостя ключ лимита — IP |

Гость — главная дыра: он единственный, кого невозможно ни узнать, ни забанить надолго.

## 2. Что уже есть

| Мера | Где | Что покрывает |
|---|---|---|
| Rate-limit 90 запросов/мин на пользователя (по JWT) или на IP | `plugins/security.ts`, общий для реплик через таблицу `rate_limits` | грубый перебор с одного аккаунта / IP |
| Отдельные жёсткие лимиты на входы (`/api/auth/*`: 5–20 в минуту) | `routes/auth.ts`, `corporate-auth.ts` | массовое создание гостевых сессий с одного IP |
| Одно сообщение на тикет одновременно (`busy_until`) | `tickets.tryLock` | параллельные запросы в один тикет |
| Тело ≤ 16 КБ, сообщение ≤ 2000 символов, имя ≤ 64 символов | `BODY_LIMIT_BYTES`, Zod-схемы | раздувание промпта |
| Дневные лимиты: 4 заявки, 3 просьбы о человеке | `DAILY_*`, таблица `daily_user_counters` | спам заявок в очередь операторов |
| Гость не может создать заявку и не видит внутренние статьи | `catalog.scope === 'guest'` | атака на очередь операторов через гостя |
| Кэш ответов на вопросы (24 ч) | `answer_cache` | повтор одного и того же вопроса не идёт в модель |
| Кэш промпта на стороне модели | `cache_control` в транспорте Anthropic | системный промпт не оплачивается заново |
| Таймаут модели, `maxRetries: 1` | транспорт | зависшие запросы не копятся |

Чего нет: лимита именно на **обращения к модели** (лимит считает HTTP-запросы, а `GET` истории и
`POST` сообщения стоят по-разному), потолка расходов в деньгах и способа отличить браузер от
скрипта на гостевом входе.

## 3. Варианты защиты

Порядок — от дешёвых и безопасных к тяжёлым. Оценки: **цена** — часы разработки, **риск** —
насколько мешает честным пользователям.

### 3.1. Отдельный, более скупой бюджет модели для гостей — рекомендуется первой

Считать не HTTP-запросы, а вызовы модели, и вести отдельные счётчики для гостя: например
**10 сообщений в час и 30 в сутки** на гостевую сессию плюс **60 в час на IP** (все гости за одним
NAT общежития). Сверх лимита гость не получает отказ — переводится в режим «только база знаний»
(BM25 + готовые статьи, без модели), который в проекте уже есть как «упрощённый режим» при
недоступной модели.

- Цена: ~3 ч. Механика есть: `daily_user_counters` + `rate_limits`, нужно добавить окно «час» и ключ
  по IP для гостей.
- Риск: низкий — честный гость задаёт 2–3 вопроса, а не 30.
- Плюс: делает бессмысленным перебор гостевых сессий с одного IP.

### 3.2. Глобальный предохранитель по расходу (circuit breaker)

Сумма токенов за час/сутки по всем пользователям (уже пишется в `daily_stats.input_tokens /
output_tokens`) сравнивается с потолком из конфига (`LLM_DAILY_TOKEN_BUDGET`). При превышении:
сначала гости уходят в режим без модели, затем — все, с сообщением «помощник временно отвечает
только по базе знаний». Оператору в консоли — плашка.

- Цена: ~2 ч.
- Риск: средний — при неверно выставленном потолке страдают все; поэтому две ступени (гости → все).
- Это единственная мера, которая гарантирует **верхнюю границу счёта** за месяц.

### 3.3. Проверка «это браузер» на гостевом входе — Cloudflare Turnstile

Невидимая капча на кнопке «Я гость»: токен проверяется на сервере при `POST /api/auth/dev`
(scope=guest). Сессия без токена не выдаётся. Turnstile бесплатен, не показывает картинки, работает
без аккаунта Cloudflare у пользователя; проект уже использует Cloudflare Worker для Telegram, так
что аккаунт есть.

- Цена: ~2 ч (виджет на экране входа + один запрос к `siteverify`).
- Риск: низкий; в Mini App не нужна — там подпись Telegram.
- Ограничение: защищает только создание сессии. Скрипт с уже полученным токеном не остановит —
  поэтому нужна вместе с 3.1.
- Альтернатива без внешнего сервиса: proof-of-work в браузере (несколько сотен мс вычислений на
  вход). Дешевле в зависимостях, но слабее: ботам это стоит столько же, сколько людям.

### 3.4. Короткая жизнь гостевого токена и привязка к IP

Сейчас JWT живёт `JWT_TTL` для всех. Гостю достаточно **1 часа**, а в claims можно положить хэш IP и
сверять при каждом запросе: украденный или «расшаренный» токен из другой сети перестаёт работать.

- Цена: ~1 ч.
- Риск: низкий; мобильные сети меняют IP, но гость просто войдёт снова.

### 3.5. Дедупликация и «тишина» на очевидный мусор

Перед вызовом модели: одинаковое сообщение от того же пользователя за последние N минут — ответ из
истории; сообщение из одних повторяющихся символов/эмодзи или длиной < 3 символов — шаблонный
ответ без модели; более 3 сообщений подряд без паузы 2 с — мягкая задержка ответа (1–3 с, растущая).
Уже есть определитель «болтовни» (`isSmalltalk`) и кэш ответов — это расширение той же идеи.

- Цена: ~2 ч.
- Риск: низкий.

### 3.6. Очередь к модели с приоритетами вместо параллельных вызовов

Семафор на число одновременных вызовов модели (например, 8) с приоритетом: сотрудник/студент >
гость. Гости при перегрузке ждут или получают «упрощённый режим». Защищает не бюджет, а
**время ответа** для настоящих пользователей во время атаки.

- Цена: ~3 ч (в памяти реплики; общая очередь между репликами — через Kafka, дороже).
- Риск: средний — при неверном размере семафора очередь растёт.

### 3.7. Периметр: Caddy / Cloudflare перед API

На уровне обратного прокси: лимит соединений на IP, ограничение скорости по пути `/api/tickets/*`,
блокировка известных ботовых User-Agent, при переносе домена за Cloudflare — их «Bot Fight Mode» и
WAF бесплатно. Это первая линия, которая отсекает тупой флуд, не доходя до Node.

- Цена: ~1 ч конфигурации.
- Риск: низкий; не знает про пользователей, только про IP.

### 3.8. Наблюдаемость (без неё остальное слепо)

Метрики: вызовы модели в минуту по scope (guest/full), токены в час, доля ответов «без модели»,
429 в минуту, top-10 IP по запросам. Алерт в Telegram операторам при превышении. Расход токенов
уже пишется в `daily_stats` — достаточно расширить `/api/operator/stats` и добавить строку в
сводку консоли.

- Цена: ~3 ч.

## 4. Рекомендуемый порядок

1. **3.1 + 3.2** — бюджет гостей и глобальный предохранитель. Закрывают деньги, дёшевы, не мешают
   людям. С них надо начинать.
2. **3.3 + 3.4** — Turnstile и короткий гостевой токен. Убирают массовое создание сессий.
3. **3.7** — лимиты на Caddy. Час работы, снимает нагрузку с Node.
4. **3.5, 3.6, 3.8** — по мере появления реального трафика и статистики.

## 5. Что не стоит делать

- **Требовать регистрацию от гостей.** Гость — абитуриент, который спрашивает адрес приёмной
  комиссии; барьер входа убьёт сценарий, ради которого гостевой режим есть.
- **Классическая картиночная капча.** Раздражает, плохо на телефоне, ломается скринридерами; Turnstile
  решает то же без картинок.
- **Ключ лимита только по IP.** Общежитие за одним NAT — сотни честных людей на один адрес; поэтому в
  3.1 лимит на IP заметно выше лимита на сессию и включается только для гостей.
- **Банить навсегда.** Гостю это ничего не стоит (новая сессия), а честному человеку с общим IP —
  стоит доступа. Только временные окна.

## 6. Что понадобится в конфиге (набросок)

```
GUEST_LLM_PER_HOUR=10        # вызовов модели на гостевую сессию в час
GUEST_LLM_PER_DAY=30
GUEST_IP_LLM_PER_HOUR=60     # на IP, только гости
LLM_DAILY_TOKEN_BUDGET=0     # 0 = без потолка; иначе сумма input+output за сутки
GUEST_JWT_TTL=1h
TURNSTILE_SECRET=            # пусто = проверка выключена (dev)
```

Все меры деградируют мягко: при превышении пользователь получает ответ по базе знаний, а не
ошибку. Это принцип, который уже заложен в «упрощённый режим» движка.
