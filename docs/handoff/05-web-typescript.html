Сайт и Mini App: остаются, подключаются к новому серверу

Что в веб-части не меняется, что меняется (типы из OpenAPI), и какие элементы интерфейса проверяет сквозной тест.

Роль одним абзацем

Веб-часть — сайт и три Mini App (Telegram, VK, MAX) — не переписывается. Это один React-код с адаптерами платформ, он уже работает и ходит в API по HTTP; какой язык на сервере — ему всё равно. Твоя работа в переезде: (1) перейти на типы, сгенерированные из OpenAPI модуля shared, (2) держать e2e-тест зелёным против нового сервера, (3) вести дизайн-систему, которую Android повторит в Compose.

Что меняется по факту

  1. lib/api.ts: убрать ручные интерфейсы ответов, импортировать из api.types.ts. Методы и SSE-парсер — как были.
  2. Если Серверный поменяет путь или поле — CI упадёт на типах, а не в проде. Это и есть смысл шага.
  3. Дизайн-токены вынести в design/tokens.json (цвета, радиусы, отступы) и генерировать из него :root в CSS и Kotlin-объект для Compose — полчаса, снимает вопрос «одинаково ли выглядят приложение и сайт» навсегда.

Поведение, которое e2e проверяет (не ломать селекторы)

  • Кнопка «Я студент или сотрудник ТПУ», поле «Ваше имя», кнопка «Войти».
  • Поле ввода с placeholder «Опишите проблему…»; после эскалации — «Написать специалисту…».
  • Текст ответа содержит «Попробуйте по шагам»; заявка — «Заявка №XXXXXXXX создана».
  • Консоль: «в очереди сейчас», «Ждут специалиста», элемент очереди .item с чипом «ждёт ответа», кнопка «Взять себе», поле «Ответ пользователю…», кнопка «Отправить».
  • Чат пользователя: «У специалиста: …».

Критерий готовности

  • Сборка без ручных типов API; e2e зелёный против Kotlin/Java-сервера.
  • design/tokens.json существует и из него собираются CSS-переменные.
