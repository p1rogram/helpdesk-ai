«Помоги мне» в браузере: как выглядит сейчас

Макеты собраны из настоящих токенов и компонентов приложения (apps/web/src/styles.css), а не нарисованы заново — то, что здесь, то и на экране. Для дизайнера: что есть, что зафиксировано, что можно улучшать.

Бриф дизайнеру

Продукт. Чат поддержки университета: студент описывает проблему, помощник отвечает пошагово, при необходимости передаёт специалисту. Три поверхности: сайт (десктоп и телефон), Mini App внутри Telegram/VK/MAX (только телефон, см. мобильный дизайн), Android-приложение.

Аудитория. Студенты 17–25 и сотрудники; часть пользователей — на телефоне в общежитии с плохим интернетом; операторы поддержки — за столом на большом мониторе весь день.

Что зафиксировано и почему.

  • Светлая тема по умолчанию — показывают на проекторе и в аудиториях; тёмная — по переключателю или от темы мессенджера.
  • Внутри Telegram цвета приходят от мессенджера (themeParams): фон, текст, кнопка. Наши токены должны уметь принять чужие значения — палитра не может опираться на конкретный оттенок синего.
  • Ответ печатается потоком — пузырь помощника растёт по мере прихода текста; статусы «Определяю суть…», «Подбираю решение…» видны 1–3 с.
  • Кнопки быстрых ответов — главный способ взаимодействия после ответа («Помогло / Не помогло», варианты уточнения). Их не больше 4, они всегда над полем ввода.
  • Шаги решения — нумерованный список внутри пузыря; это самый читаемый элемент, его нельзя сжимать.
  • Категория обращения пользователю не показывается (только в карточке справа и у оператора).
  • Системный шрифт (без загрузки веб-шрифтов) — Mini App должна открываться мгновенно.

Где точно есть что улучшать.

  • Правая панель «Карточка» на десктопе выглядит служебно: статус, уверенность, поля — можно сделать понятнее человеку, а не разработчику.
  • Экран входа: пять кнопок провайдеров одинаковые — нужна иерархия (основной вход вуза vs гость).
  • Консоль оператора: сводка из шести одинаковых плиток; чипы состояний («ждёт ответа», «новое сообщение», «помощник», «через help.tpu.ru») — разные по смыслу, а по форме одинаковые.
  • Пустые состояния («Пока у вас нет обращений») — сейчас иконка + текст, без характера.
  • Иконки — набор из Icon.tsx, разного веса; нужен один комплект.
  • Оценка звёздами после закрытия — стандартная; можно найти форму под «помогло/не помогло + комментарий».
Формат передачи: любые правки цветов/радиусов/отступов — через токены (таблица ниже) → один файл design/tokens.json, из которого собираются CSS и Compose. Правки компонентов — в терминах компонентов ниже, у каждого есть имя в коде.

Как отдавать правки

  • Цвета, радиусы, тени, отступы — как значения токенов из таблицы выше. Если нужен новый токен — с именем и ролью.
  • Компоненты — по именам из галереи (MessageBubble, StepList, QuickReplies, Composer, TicketCardPanel, chips, escalated bar). У каждого — состояния: обычное, hover, disabled, тёмная тема, внутри Telegram.
  • Экраны — три ширины: телефон 390, планшет/узкий десктоп 700–1000, десктоп 1000+.
  • Всё, что зависит от мессенджера (цвета, шрифт, safe-area), — в мобильном документе.
