Роль · ИИ и поиск · Kotlin

Модель, промпты, эмбеддинги, RAG, бюджет

Связь с Qwen на DGX Spark, разбор JSON, поиск по каталогу и документации, защита бюджета и оценочный прогон качества.

Роль одним абзацем

Ты отвечаешь за всё, что связано с моделями и поиском: как сервер разговаривает с LLM (на Spark вуза или в облаке), какие промпты отправляет, как разбирает JSON, как ищет по каталогу и документации (BM25 + векторы), как считает бюджет. И за оценочный прогон — доказательство, что выбранная локальная модель справляется. Ты же — контакт с администраторами GPU-сервера. Модуль ai/ на Kotlin.

Целевая конфигурация: Qwen3-30B-A3B (FP8) через vLLM на NVIDIA DGX Spark + эмбеддер deepvk/USER-bge-m3 через /v1/embeddings там же. Облако (Claude) — запасной провайдер, переключается конфигом.

Что попросить у администраторов Spark

# vLLM как постоянный сервис (NGC-образ arm64), доля памяти — чтобы соседи не уронили
vllm serve Qwen/Qwen3-30B-A3B-FP8 --max-model-len 8192 --gpu-memory-utilization 0.35 --port 8000
vllm serve deepvk/USER-bge-m3 --task embed --port 8001
# нам нужны: URL обоих, ключ (если включат), доступность с сервера API по сети

В .env API: LLM_PROVIDER=openai, LLM_BASE_URL=http://spark:8000/v1, LLM_MODEL=Qwen/Qwen3-30B-A3B-FP8, RAG_EMBEDDINGS=remote, RAG_EMBEDDINGS_URL=http://spark:8001/v1, RAG_EMBEDDING_MODEL=deepvk/USER-bge-m3. Переменные RAG_EMBEDDINGS=remote и RAG_EMBEDDINGS_URL — новые, их добавляешь ты.

Оценочный прогон — обязательная задача

  1. Собрать 30–50 реальных обращений (с ИТ-службы, обезличенных) + ожидаемую категорию и статью.
  2. Прогнать через analyze на Qwen3 и на Claude; посчитать: доля невалидного JSON, точность категории, полнота извлечения полей.
  3. Прогнать solve: глазами оценить «дописал от себя», русский язык, длину.
  4. Поиск: доля запросов, где нужный фрагмент в топ-3, для e5-small vs USER-bge-m3.
  5. Результат — таблица в docs/EVAL.md. По ней решается: остаёмся на 30B-A3B или берём Qwen3-32B 4-bit; ужесточать ли промпт solve.

Порядок работ

нед. 1
Интерфейсы и BM25LlmService/LlmTransport/SearchService как интерфейсы для движка; порт search.ts с тестами синонимов и опечаток.
нед. 2
Транспорт к vLLMOpenAiCompatibleTransport + тест с фейковым сервером; разбор JSON → Analysis; thinking on для analyze, off для solve.
нед. 3
RAGchunker, redact, RemoteEmbedder, ingest в pgvector, гибридный поиск, кэш ответов; тесты rag.
нед. 4
Бюджет и прогонLlmBudget, /v1/embeddings на Spark, оценочный прогон, docs/EVAL.md, донастройка промптов.

Критерий готовности

  • Тесты llm-transport, rag, search, budget перенесены и зелёные.
  • Переключение провайдера (LLM_PROVIDER) и эмбеддера (RAG_EMBEDDINGS) — только конфигом, без правок кода.
  • docs/EVAL.md с цифрами по локальной модели.
  • Модель никогда не роняет чат: любая ошибка → LlmUnavailableException → движок идёт по fallback.
